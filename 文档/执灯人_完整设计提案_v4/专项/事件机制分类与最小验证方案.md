EVENT-COVERAGE-1.0 · 2026-10-27。按用户确认，后续按机制复用、按风险验证，不再为每张事件卡建立独立模块和一套完整远征。本文是能力与覆盖清单；任务顺序统一登记在[开发总路线图](../../../开发总路线图_执行版.md)的“事件灰盒当前工作”小节。

## 2 提取的共用流程与真实缺口

以下保留0.10盘点时的实现边界；0.11已落实共用案件操作、分账交易和EV25接收，未开放剩余六张人性卡。字段仍单一持有，不复制第二份案件状态。

| 共用能力 | 已有基础 | 尚需补齐 |
| --- | --- | --- |
| 选择事务 | `Game.execute`整体保存失败回滚；普通事件共用费用、收益与现场回执 | 保持入口统一，不为同一事务复制事件专用保存逻辑 |
| 案件状态与续办 | EV03／09／19各有原对象、首次地点、实际接收、唯一凭单与续办 | 将共有字段和操作收敛到按事件ID登记的案件逻辑；保留护送、载重、早返各自生命周期，不做一个含糊的“点击就完成”函数 |
| 现场完成 | 数据已定义LOCAL及EV25认领员回执 | 通用现场动作：核对对象与实际现场服务→完成卡片规定动作→提交回执与互斥终态。EV25交给认领员；不能把其他LOCAL一律描述成收件人收货 |
| 一次性交易兑现 | 三项已接入案件处理铜、公共结晶与补给；败战也保留凭单 | 铁料／晶屑进入材料仓，不混作公共结晶；装备需选适用家族、固定品质与数量，并处理容量不足时保留待兑现权。现有`bank[key] += value`不能直接接这些奖励 |
| 叙事与地图约束 | 章节／区域／服务抽样，独立普通人文本层，灯光元数据 | 核对EV27真实ST-303事实门槛；不能用CH3替代。有人作业地点需局部光源，EV03／07藏身者可无灯；光源不提供免疫 |
| 历史联动 | EV53→54、EV56→55已经以额外互斥选项接入 | 未来联动读取实际完成记录；有历史不等于有当前物资，更不等于已送达。保持原选项与随机性 |

建议案件配置只表达：事件ID、主机制、原对象／接洽地点、完成动作与回执、接收服务、收益包、永久后果、续办说明和玩家文本。执行器负责前置检查、实际动作、原子提交与返程钩子。普通卡继续使用现有效果解释器；不为统一结构而大改无关战斗代码。

交易收益需要区分的配置范围：EV03为铜＋补给；EV05／09／19为铜＋公共结晶；EV16为铜＋铁料；EV25为铜＋晶屑；EV07／28为铜＋Q2装备（1／2件）；EV12为晶屑＋Q2装备；EV22为铜＋Q3装备。品质与家族选择规则复用正式合同，不把装备折算成铜以绕过未实现能力。

## 3 最小验证安排

**全部卡做轻量配置检查，代表机制做实跑，新差异做针对性检查。** “不逐卡实跑”不等于任由错误ID、配方、人物或报酬进入内容池。

| 层次 | 核对内容 | 何时做、何时停止 |
| --- | --- | --- |
| 全池配置 | ID／引用、费用与收益类型、配方／候选、章节与事实门槛、接收服务、回执唯一、免费暂离、玩家文案与光源例外 | 内容批次导入或相关配置修改时；未知效果直接报缺口，不能默默跳过。检查完配置不额外重跑60趟 |
| 共用事务 | 重复操作、互斥选择、读档、保存失败回滚、金额与物品入正确账本 | 改动共享执行逻辑时运行对应自动测试；这些异常不要求每张卡各做一次人工操作 |
| 代表流程 | ESCORT复用EV03证据；CARGO复用EV09；RETURN复用EV19；LOCAL用EV25补一个代表 | 未改的机制引用既有证据；新增LOCAL只验证正常当场接收、失败／重复、后续败战不抹掉已完成事实等差异 |
| 奖励差异 | 一种材料入仓、单件／多件装备、家族选择、满仓待兑、重复兑现 | 按奖励处理分支选配置，不为每张含装备的卡另跑完整远征 |
| 组合与玩法 | 暂离→获取条件→回访；载货期间另一事件导致早返；真实历史联动；完成交割后败战 | 机制接通后选少量能覆盖这些关系的路线，明确抽样条件。异常状态可用受控测试，但不包装成自然游玩 |
| 玩家体验 | 选择是否可理解、实际牺牲多大、补给是否足够、被迫早返是否有趣 | 在短／中／长途代表试玩中记录，不用自动化通过数量代替判断；无需每趟收齐事件 |

十项原始故事仍保留各自人物与后果。若出现新机制（例如改变地形、触发额外战斗），或者现有生命周期产生实际冲突，才新增对应代表；不因换了故事标题就增加一整套流程。
