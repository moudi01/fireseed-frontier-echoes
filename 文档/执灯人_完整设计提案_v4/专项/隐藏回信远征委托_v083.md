# 隐藏回信：中段远征委托

2026-10-31，接入 TINDER-GREYBOX-0.83。

三份回信对证（assemble）之后，玩家从所选三份回信中选一名接应对象，再选接应方式。目标地区取自该回信的真实原现场；接单前公开各对象的地区、两种方式及费用，不增加随机事件或重抽已有事件。

| 方式 | 出发成本 | 实际行动 |
| --- | --- | --- |
| 随队补给 SUPPLY | 可达目标地区的普通路线出发时额外支付2补给 | 到目标地区S救护站，显式交接；不消耗治疗机会，不要求有人缺血 |
| 现场取证 TRACE | 无额外补给，普通出发费照常 | 本趟真实打赢目标地区G门战后，到X出口显式接收；不要求能够露营 |

补给在相关路线出发时支付；改走另一支、提前归城或败战均不退，每次重试重新支付。目标不在路线中则不绑定、不收费。两种方式都不占消耗品格，也不改变消耗品的已用占位。

先在城镇登记：

```text
thread status
thread commission SUPPLY EV03 CONFIRM
# 或 thread commission TRACE EV03 CONFIRM
```

接单后方式与对象固定，重复同命令不重新扣款或刷新。随后正常出发，在指定接应点执行：

```text
thread deliver CONFIRM
```

交接只取得待带回的凭据，不能立刻推进回信。同趟实际安全归城后才完成；已经交接的安全撤退可以完成，败战或未交接的归城不能完成，后续普通远征可重试。固定事件专线、救援、演练、调试强制胜利不能代替普通委托。

完成委托后，follow仍需原7案、至少3种接应类型；answer仍需全部10案的原人原物回执、没有不可撤销的售出和真实研究交付，且必须显式答信。人员永久损失／未救回仍影响完美结局。阅读、因子100或仅完成委托不会自动得到完美结局。

实现只改`hidden_thread.py`与`engine.py`。委托独立维护登记、每趟出发付款、现场签收、同趟归城与完成证明，不复用消耗品占位字段。旧0.82档使用`play_v082.py`读取，不修改版本或来源戳。
